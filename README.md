# Figura Lab — сайт бренда

Figura Lab by Елена Бастуева — wellness-проект о питании, мягком снижении веса и
нормализации пищевых привычек. Репозиторий содержит сайт бренда. Сейчас это
одностраничный MVP главной страницы, который поэтапно превращается в
многостраничный сайт по `FIGURA_LAB_MASTER_PLAN_FINAL.md`.

**Текущий этап: Design System + Visual Direction.** Ведётся в ветке
`stage-2-design-system`, ещё не влита в `main`. Stage 0 в `main`, Stage 1
(accessibility) — в своей ветке. Это визуальный проход по существующей
одностраничной версии: структура страницы и контур доступности Stage 1
сохраняются. Content foundation (Stage 2 по FINAL PLAN) не начат.

Это репозиторий разработчика, а не рекламный материал. Все правила ниже
обязательны к соблюдению.

## Стек

| Слой | Решение |
| --- | --- |
| Разметка | HTML5, один файл `index.html` |
| Стили | CSS3, кастомные свойства, без препроцессоров |
| Скрипты | Vanilla JS, IIFE, без модулей и сборки |
| Шрифты | Self-hosted woff2 (Cormorant Garamond + Manrope variable) |
| Изображения | WebP + JPEG fallback, `<picture>` + `srcset` |
| Сборка | Отсутствует — статические файлы отдаются как есть |
| Зависимости | Нет `package.json`, нет `node_modules` |

Фреймворки, UI-киты и animation-библиотеки не используются осознанно.
React, Next.js, Vite, Tailwind, Bootstrap подключать нельзя.
Eleventy появится только на Stage 3 (многостраничная архитектура).

## Запуск локально

Сборки нет, но открывать `index.html` через `file://` не нужно: относительные
пути шрифтов и `<picture>` корректнее проверять по HTTP.

```bash
# Python 3
py -m http.server 8000
# или
python3 -m http.server 8000
```

Затем открыть `http://localhost:8000/`.

Проверять минимум на трёх ширинах: 375, 768, 1440.

## Медиа-пайплайн

Исходник лежит в `source-images/`, публикуемые варианты собираются в
`assets/img/elena/` и коммитятся. Генерация выполняется вручную через ffmpeg:

```bash
# WebP
ffmpeg -y -i source-images/elena-hero.png -map_metadata -1 \
  -vf "scale=1040:-2:flags=lanczos" \
  -c:v libwebp -pix_fmt yuv420p -preset photo -compression_level 6 -quality 86 \
  assets/img/elena/elena-hero-1040.webp

# JPEG fallback
ffmpeg -y -i source-images/elena-hero.png -map_metadata -1 \
  -vf "scale=1040:-2:flags=lanczos" \
  -c:v mjpeg -pix_fmt yuvj420p -q:v 3 \
  assets/img/elena/elena-hero-1040.jpg
```

Ширины набора: 400, 520, 800, 1040. `-map_metadata -1` обязателен — вычищает
EXIF, включая геометки. Бюджет LCP-варианта — не более 120 KB.

AVIF, автоматизация пайплайна и минификация относятся к Stage 7.

## Дизайн-система

Зафиксирована визуальным проходом. Токены — в `:root` первого блока
`assets/css/main.css`, менять их вне визуальной стадии нельзя.

Направление: **тихий editorial**. Тёплая светлая основа, плоские поверхности
вместо ковра из закруглённых карточек, hairline-сетки вместо теней, крупная
антиква в заголовках, один глубокий тёмный блок в финале страницы.

### Цвет

| Группа | Токены | Роль |
| --- | --- | --- |
| Поверхности | `--c-ivory`, `--c-white`, `--c-linen`, `--c-linen-deep`, `--c-sand` | база и полосы-подложки |
| Текст | `--c-graphite`, `--c-graphite-soft`, `--c-graphite-mute` | тёплый графит, не чёрный |
| Тёмный блок | `--c-ink`, `--c-ink-text`, `--c-ink-text-mute` | финальный CTA и футер |
| Зелёная линия | `--c-sage-text`, `--c-olive`, `--c-olive-deep` | eyebrow, основная кнопка |
| Акценты | `--c-wine`, `--c-metal`, `--c-champagne` | точечно: одна строка, цифры, декор |
| Линии | `--hairline`, `--hairline-strong`, `--line-strong`, `--hairline-invert` | сетки и границы |

Правила: вино — единственный «цветной» акцент, применяется точечно (третья
строка утверждения о подходе). Металл — декор и текст на тёмном фоне, на светлом
как текст не используется (2.20:1). `--c-sage-text` — самый светлый допустимый
зелёный для текста и линий (5.5:1). Границы интерактивных элементов —
`--line-strong` (≥3:1, WCAG 1.4.11).

### Типографика

* Display — Cormorant Garamond 400/500 + italic 400. Заголовки, крупные цифры,
  цитаты отзывов.
* Body — Manrope variable 400–600. Весь интерфейсный и основной текст.
* Шкала — `clamp()` от `--fs-meta` до `--fs-display`, `--fs-display` имеет
  отдельную шкалу для одноколоночной и двухколоночной раскладки hero.
* `text-wrap: balance` на заголовках, `pretty` на абзацах.

### Ритм и раскладка

* `--space-section` — базовый шаг секции, `--space-section-lg` — смысловые паузы
  (утверждение о подходе, «для кого»).
* Контейнер `--content-max` 1152px, `--bleed-inset` считает отступ для
  full-bleed блоков, чтобы их контент оставался на общей сетке.
* Радиусы малые (`4px`, `8px`): подача строится на прямых углах и линиях.
  Единственная сложная форма — арка hero-фотографии.
* Тени только две: `--shadow-soft` для плашек и `--shadow-photo` для портрета.

### Компоненты

* Кнопки: `.btn-primary` (оливковый градиент), `.btn-line` (контурная),
  `.btn-invert` (на тёмном). Состояния default / hover / focus-visible / active
  у всех трёх.
* Секции сознательно разные: hairline-сетка «изменений», полоса linen с крупными
  цифрами в «почему», асимметричная раскладка со sticky-интро в «для кого»,
  горизонтальная лента отзывов, тёмный финальный блок.
* Бренд — текстовый: `.brand-mark` рассчитан на подстановку финального логотипа
  (`<img>`/`<svg>` той же оптической высоты) без правки раскладки шапки.
  Собственный логотип не придумывался.

### Технические ограничения системы

* `backdrop-filter` не ставится на `.site-header` напрямую — только на
  `.site-header::before`. На самой шапке он создаёт containing block для
  `position: fixed`, и оверлей мобильного меню считается от шапки, а не от
  вьюпорта (меню открывалось полосой в 80px).
* `visibility` у `.site-nav` гасится с задержкой на длительность закрытия и
  включается мгновенно: иначе `focus()` по первой ссылке сразу после открытия
  не срабатывает.

## Git workflow

* `main` — только отревьюенный код. Прямые коммиты в `main` запрещены.
* Одна стадия roadmap = одна ветка = один коммит-набор = один review.
* Имя ветки: `stage-<N>-<короткое-имя>`, например `stage-0-foundation`.
* Ветка не мержится, пока не пройдены тесты соответствующей стадии из
  `FIGURA_LAB_MASTER_PLAN_FINAL.md` (раздел 23).
* Стадии не смешиваются в одной ветке.

### Ветки сейчас

| Ветка | Содержимое | Статус |
| --- | --- | --- |
| `main` | MVP + Stage 0 Foundation + документы плана | эталон |
| `stage-1-accessibility` | Stage 1, accessibility и UX foundation | ожидает human review |
| `stage-2-design-system` | design system и визуальное направление | ожидает human review |

Production deployment из рабочих ветвей не выполняется. Публикация вообще
не выполняется ни из одной ветки: боевой хостинг и домен выбираются только на
Stage 9. GitHub Pages, если понадобится, остаётся demo-площадкой — там нельзя
задать HTTP-заголовки, поэтому CSP и HSTS на ней не проверяются и в зачёт
security-стадии не идут.

## Доступность: действующие правила

Контур, заданный на Stage 1. Ломать его в следующих стадиях нельзя.

* Skip-link «Перейти к основному содержанию» — первый focusable элемент `body`,
  ведёт на `main[tabindex="-1"]`.
* Фокус: единая система `:focus-visible` (`2px solid var(--c-graphite)`,
  `outline-offset: 3px`, на тёмных блоках — `var(--c-ink-text)`).
  `outline: none` допустим только для `main` как цели skip-link и должен
  оставаться единственным вхождением в CSS.
* Цвет текста: `--c-sage-text` для текста и ссылок, `--c-olive` и `--c-metal` —
  фоны и декор. Текстовые пары держат ≥ 4.5:1, границы интерактивных элементов —
  ≥ 3:1 через `--line-strong`. Замер при любой правке палитры.
* Тач-таргеты: `min-height: 44px` у ссылок навигации, футера, бренд-ссылки,
  бургера и кнопок.
* Мобильное меню: `aria-expanded` и `aria-label` переключаются, фокус уходит на
  первую ссылку, Tab заперт внутри меню, Escape закрывает и возвращает фокус на
  бургер, фон получает `inert`, скролл блокируется классом `body.nav-locked`
  (inline-стилей нет — требование CSP).
* Якоря: `scroll-padding-top` на `html` и `scroll-margin-top` на `main` и
  секциях — заголовок не уходит под sticky-шапку.
* `prefers-reduced-motion: reduce` покрывает reveal, glow, hover-подъёмы,
  `:active`, анимацию бургера, skip-link и smooth-scroll.
* `.reveal:focus-within` раскрывает блок мгновенно: клавиатура может дойти до
  секции раньше, чем сработает observer, и сфокусированный элемент не должен
  оставаться невидимым.
* Без JS страница остаётся читаемой: скрытое состояние `.reveal` и оверлей-меню
  живут внутри `@media (scripting: enabled)`. В этом режиме навигация — видимая
  переносимая строка, а шапка не `sticky`: её высота перестаёт совпадать с
  `--header-h`, и sticky накрывала бы цели якорей.

### Осознанно отложено

* Перенос бургера с 640px на 900px (`FINAL PLAN`, раздел 9) — вместе с
  расширением меню до пяти пунктов на Stage 3. Сейчас пунктов четыре, на
  641–960px они размещаются без наложения.
* Видимые стрелки у скролл-блока отзывов (`FINAL PLAN`, раздел 15). Индикатор
  позиции добавлен визуальным проходом: дорожка под лентой показывает прогресс и
  появляется только когда контент реально шире вьюпорта. Клавиатурный доступ
  был и остаётся: контейнер — `role="region"` с `tabindex="0"`. Кнопки-стрелки —
  вместе с перестройкой блока на Stage 4.
* `aria-current` и подсветка активного раздела по IntersectionObserver — Stage 3,
  вместе с многостраничной навигацией.
* ~~Граница `.btn-ghost` и `.nav-cta` не добирает 3:1 по WCAG 1.4.11~~ — закрыто
  визуальным проходом: контурная кнопка называется `.btn-line`, границы кнопок и
  `.nav-cta` берут `--line-strong` (#8c8880, 3.36:1 на ivory).
* Медиа-фича `scripting` требует Chrome 120+, Safari 17+, Firefox 113+. В более
  старых браузерах блок не матчится, деградация идёт в безопасную сторону:
  контент виден, а мобильная навигация становится переносимой строкой без
  бургера. Пересмотреть, если в аналитике появится существенная доля таких
  браузеров (аналитика — Stage 10).
* `body.nav-locked` использует `overflow: hidden`. На iOS Safari это не всегда
  полностью блокирует rubber-band за оверлеем; надёжный вариант требует
  `position: fixed` с сохранением scrollY, то есть записи inline-стилей, от
  которых отказались ради CSP. Оверлей закрывает вьюпорт и имеет
  `overscroll-behavior: contain`, поэтому проблема косметическая. Решается на
  Stage 7 вместе с проверкой на реальных устройствах.
* Автоматические прогоны Lighthouse и axe на Stage 1 не выполнены: в окружении
  нет браузерного рантайма, а ставить Chromium ради теста запрещено регламентом
  стадии. Вместо этого выполнен статический аудит разметки, CSS и геометрии,
  расчёт контраста по формуле WCAG и поведенческий прогон `site.js` против
  мок-DOM. Прогон в реальном браузере обязателен на Stage 5 и Stage 10.

## Secrets

В репозитории не должно быть секретов ни в каком виде:

* API-ключи, токены, пароли, приватные ключи;
* токены Telegram/MAX-ботов;
* строки подключения и креды хостинга;
* файлы `.env` с реальными значениями.

Токен бота во фронтенде недопустим — любая интеграция с мессенджерами делается
через серверную часть на Stage 9. При появлении конфигурации использовать
переменные окружения хостинга и `.env.example` без значений. Если секрет попал
в историю — считать его скомпрометированным и отозвать.

## Правила изменений

* Дизайн не переделывается вне стадии, которая это явно предусматривает.
* Палитра, типографическая пара, spacing и композиция зафиксированы разделом
  «Дизайн-система». Точечные правки внутри системы допустимы, замена системы —
  только отдельной визуальной стадией.
* Массовый rewrite `index.html`, `main.css` и `site.js` не допускается —
  только точечные правки.
* Перемещение файлов — через `git mv`, с обновлением путей.
* Нерабочих ссылок и элементов-пустышек в интерфейсе быть не должно.
